# project-state 蓝图
> 活蓝图：正文永远是当前真相，改了就覆盖。只讲功能不讲实现。
> 重构照本文行为契约重写即可；未列为硬约束的一切都是实现细节，可自由更改。

## 1. 一句话
同一个 git 仓库开了多个 worktree、又有多个 AI 会话（Claude Code / Codex）先后或同时干活时，给它们一块共用的任务交接板：谁在哪个工作区做什么、停在哪、下一步、在等什么、哪些未提交改动为什么要留着。它存的是"现在"，长期结论和教训仍归记忆。

## 2. 功能与行为 + I/O 契约
- **看现场（status）**：在仓库内任意目录运行 → 打印仓库名与任务目录；列出 git 登记的每个 worktree（路径、分支、HEAD 短哈希、"干净"或"改动 N，未跟踪 M"，目录不存在或读不了就明说），当前所在的那个带 `*`；再列活跃任务：短名、标题、状态、所属工作区（当前的标"（当前）"）、多久前更新，以及「停在哪 / 下一步」节的第一行。任务 7 天以上没改过标"久未更新，内容可能过期"；任务登记的工作区已不在 git 登记里标"工作区已不在 git 登记里，基线待核实"。
- **新建任务（new <短名> --title <标题> [--status 进行中|阻塞|待办]）**：按模板生成任务文件，自动填上当前 worktree 根路径和当前分支，打印文件路径。短名只许字母、数字、下划线、点、横线，不合法退出 2；同名已存在退出 1，不覆盖。
- **做完（done <短名>）**：把任务移到 `done/<YYYYMMDD>-<短名>.md`，此后不再出现在看板和注入里；不存在退出 1。
- **任务目录（path）**：打印本仓库的任务目录（不存在就建）。
- **会话开始注入（hook）**：从标准输入读宿主给的 JSON（取 `cwd`、`hook_event_name`）。不在 git 仓库里、或本仓库没有活跃任务 → 什么都不输出，退出 0。有活跃任务 → 输出一段上下文：上面的看板 ＋ 当前 worktree 名下任务的全文（合计超过 4000 字就不贴全文、只列路径并要求读完，绝不截断）＋ 使用规则（接着对应任务干、只动当前工作区的任务、进展和交接写进任务文件、未提交改动写清为什么留着、git 能查到的清单不用抄、进度不写进记忆），规则里附带可直接执行的本工具绝对路径调法。
- 所有命令默认按当前目录识别仓库，`--cwd <目录>` 可指定；从哪个 worktree、哪个子目录进来，看到的都是同一份任务。
- **和别处的分工（同一件事的进度只记一处）**：有 vibe-flow `HANDOFF.md` 的项目，进度和交接只写 HANDOFF，不在本板另建任务；本板管没有 HANDOFF 的仓库（公司仓等）。平台原生记忆和 hub 金库只存长期结论和教训，不记进度，看到进度类记忆以 git log 和这两处为准。session-sweep 只是发现入口，从它那里捡起的事进度落回 HANDOFF 或本板。
- **AI 主动建任务**：在没有 HANDOFF 的仓库里，AI 判断出一件事一个会话做不完、会换 AI 接手，或要留未提交改动等评估时，当场 `new` 一个任务并在回复里告诉用户一句，不等用户说"记个任务"。一问一答、当场做完的小事不建。

**I/O / 数据契约**：
- 任务目录：`%LOCALAPPDATA%\ai-project-state\<仓库目录名>-<git common dir 规范化路径的 sha1 前 8 位>\`（环境变量 `PSTATE_HOME` 可改根目录）。内含 `repo.txt`（记录 git common dir）、`tasks\<短名>.md`（活跃）、`done\`（已完成）。
- 任务文件：UTF-8 明文 `.md`。第一行 `# <标题>`；标题下 `- worktree: <路径>`、`- 分支: <分支>`、`- 状态: <进行中|阻塞|待办>`；四节 `## 目标`、`## 停在哪 / 下一步`（第一行就是看板显示的下一步）、`## 阻塞 / 在等什么`、`## 保留的未提交改动（为什么不提交、哪些不能覆盖）`。人和 AI 用普通文件编辑直接改，更新时间取文件修改时间。
- 注入输出：`{"hookSpecificOutput": {"hookEventName": <事件名>, "additionalContext": <文本>}}`，UTF-8。

## 3. 边界 / 明确不做
- 不做认领锁 / 文件级锁：手写认领证明不了对方还在干活，比没有更误导。冲突防护靠"不同的活分 worktree、同一 worktree 同时只有一个写会话"。
- 不做收尾时的交接检查（Stop 钩子），先看实际会不会漏写再定。
- 不做每轮提问时的变化检测、写入前闸、带版本号的统一更新入口。
- 不手工维护改动文件清单，git 现场每次现算。
- 不进公司仓、不进 git、不进 hub 长期记忆；不做跨机器同步。
- 不替代 vibe-flow 的 HANDOFF：有 HANDOFF 的项目不在这里记进度。
- 没有活跃任务时不注入任何东西。

## 4. 硬约束 + 重构自由声明
- 状态放仓库外本机目录，按 git common dir 识别同一仓库；所有 worktree 必须落到同一份。
- 一个任务一个文件，不同会话改不同文件，不共写一整页。
- 注入钩子任何出错都放行（退出 0、不输出），绝不因为它挡住会话。
- 只用 Python 标准库。
- **以上未列出的一切均为实现细节，重构可随意更改。**

## 5. 功能痛点 / 易错点
- 仓库识别必须用 common dir，不能用 worktree 根或分支名，否则同一仓库的几个 worktree 各看各的，等于没做。
- 进度一旦写进记忆就会过期还被自动注入，误导后来的会话；这里的任务做完必须移出活跃视图。
- 任务记的工作区可能已被删除（旧 worktree），看板必须标出来，不能当作现行基线。
- 本机有 Esafenet 透明加密：`.py` 落盘是密文但 python 能跑；`.md` 实测落盘是明文，所以任务文件任何工具都能直接读写。

## 6. 平台约定
会话开始注入：
- 时机：主会话启动、恢复、清空、压缩之后。
- 需要的信息：会话当前目录。
- 预期结果：有活跃任务时，看板和当前工作区任务全文作为上下文给到模型；没有时无感。只提示，不拦。
- 出错时：放行，不输出。
- 平台缺这项能力时：只能靠 skill 描述触发，手动跑 status。

| 平台 | 能力范围 | 支持状态 / 降级表现 | 已验证范围 |
|---|---|---|---|
| Claude Code | 会话开始注入 + skill | 已支持 | 2026-09-30：钩子脚本对真实仓库手动喂 JSON 验证（无任务静默、有任务注入、非仓库静默、子目录进入）；尚未经插件安装后的真实会话验证 |
| Codex | 会话开始注入 + skill | 已接线，插件钩子需先在 Codex 里信任 | 未在真实 Codex 会话验证 |
