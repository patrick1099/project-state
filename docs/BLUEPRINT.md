# project-state 蓝图
> 活蓝图：正文永远是当前真相，改了就覆盖。只讲功能不讲实现。
> 重构照本文行为契约重写即可；未列为硬约束的一切都是实现细节，可自由更改。

## 1. 一句话
几个 Claude Code 会话同时干同一个**个人项目**时的会话互斥锁，外加一块待办看板：哪个会话正在干哪件事、占着哪些文件，别的会话写同一个文件会被拦下，由 AI 停下问用户等对方还是接手；还没开始的事记成看板条目。进度和交接不在这里，写项目的 `HANDOFF.md`。

## 2. 功能与行为 + I/O 契约

### 2.1 会话互斥锁（自动）
- **作用范围**：只在个人项目生效。个人项目 = 目标文件所在 worktree 的根有 `docs/BLUEPRINT.md`，或目标文件同目录有 `*.BLUEPRINT.md`；仓库级开关 `lock on|off|auto` 可强制开 / 关 / 回到按蓝图判断，off 优先。不在 git 里、或不是个人项目的写入，一律放行、什么都不输出、不留任何状态。
- **写入前裁决**：会话每次用 Write / Edit / MultiEdit / NotebookEdit 写文件之前，把这个文件按"在 worktree 里的相对路径"登记到本会话名下——**不同 worktree 里的同一相对路径算同一个文件**（个人仓每件活开一个 worktree，冲突要到合并时才炸）。这个文件已被另一个活会话占着 → 拦下这次写入，拦截理由给出：文件、占用者会话号、它在哪个 worktree、认领的任务、对话日志最后更新时间、是否还有写入在执行中或等待批准；并要求 AI 停下把情况告诉用户、问等对方还是接手，用户说接手就跑 `take <会话号>` 再重试，不许换 shell / python 等别的工具绕过。
- **登记即生效**：登记发生在写入之前、和裁决一起原子完成；对方写入还在执行中或等待批准时，即使文件看起来没变也照样互斥。写入失败时，只撤销这次新建、且从没写成过的占用；之前写成过的占用不因一次失败而撤销。
- **占用什么时候释放**：
  - 占用者会话的进程没了（窗口关掉、崩溃）——查不准死活时当作还活着，不释放；
  - 占用者会话结束（含 `/clear` 换会话）；
  - 占用者那个 worktree 已不存在；或那个文件在它的 worktree 里干净、不是被忽略的文件、其分支已并进集成分支（本地 `main`，没有就 `master`），且没有在途写入；
  - `release`（用 squash / cherry-pick 合并、或放弃改动时收尾用）、`take`（被别人接手）。
  - 不按超时释放。会话闲置再久，只要窗口开着就还占着，看板显示对话日志最后更新时间，由用户决定是否接手。
- **同一家不互斥**：占用者是本会话进程本身（同进程的子代理）或本会话的祖先进程（本会话起的 headless 子会话去写父会话占着的文件）→ 放行，占用仍归原占用者。同一个父会话起的两个 headless 子会话之间照常互斥。
- **接手（take <会话号前缀|条目短名>）**：用户同意后，把对方在本仓库的全部文件占用和任务认领转到本会话名下；对方之后再写这些文件会被拦。对方下一次在本仓库写任何文件时，会被拦一次并被告知"用户已让会话 X 接手你在这个仓库的活"，重试即可继续别的事。对方还有在途写入时提示"已经放行的写入撤不回"。找不到唯一的活会话 / 认领时退出 1（会话可能已结束，直接重试即可）。

### 2.2 看板
- **看现场（status）**：在仓库内任意目录运行 → 打印仓库名与任务目录；列出 git 登记的每个 worktree（路径、分支、HEAD 短哈希、"干净"或"改动 N，未跟踪 M"，目录不存在或读不了就明说），当前所在的那个带 `*`；有活会话时列出每个活会话：会话号（本会话标"（本会话）"）、认领的任务、占用几个文件、对话日志最后更新时间；再列看板条目：短名、标题、状态、被哪个会话认领、所属工作区（当前的标"（当前）"）、多久前更新，条目里有「停在哪 / 下一步」节时显示其第一行。条目 7 天以上没改过标"久未更新，内容可能过期"；条目登记的工作区已不在 git 登记里标"工作区已不在 git 登记里，基线待核实"。已经死掉的会话在读看板时顺手清掉。
- **新建条目（new <短名> --title <标题> [--status 待办|进行中|阻塞] [--force]）**：默认状态 `待办`。按模板生成条目文件，自动填上当前 worktree 根、当前分支和 `<worktree>/docs/HANDOFF.md`（进度正文写那里），打印文件路径。不是个人项目时拒绝并退出 1（用户定了公司仓不新建条目），加 `--force` 才建。短名只许字母、数字、下划线、点、横线，不合法退出 2；同名已存在退出 1，不覆盖。
- **认领（claim <短名>）**：本会话认领一条，条目状态改为 `进行中`。看板上没有这条退出 1（先 new）；已被另一个活会话认领退出 1，并告诉 AI 停下问用户、接手用 `take`。
- **放掉（release）**：放掉本会话在本仓库的任务认领和所有没有在途写入的文件占用。
- **做完（done <短名>）**：条目移到 `done/<YYYYMMDD>-<短名>.md`，此后不再出现在看板和注入里，认领随之解除；不存在退出 1。
- **任务目录（path）**：打印本仓库的任务目录（不存在就建）。
- `claim` / `take` / `release` 只能在 Claude Code 会话里运行（靠会话号环境变量认出自己），认不出退出 1。所有命令默认按当前目录识别仓库，`--cwd <目录>` 可指定；从哪个 worktree、哪个子目录进来，看到的都是同一份。

### 2.3 会话开始注入
- 从标准输入读宿主给的 JSON（取 `cwd`、`hook_event_name`、`session_id`）。不在 git 仓库里、或本仓库既没有看板条目也没有别的活会话 → 什么都不输出，退出 0。否则输出：看板 ＋ 当前 worktree 名下条目的全文（合计超过 4000 字就只列路径并要求读完，绝不截断）＋ 用法。
- 个人项目的用法：开工前对一下活会话和条目；要做的事在看板上先 `claim`，被拒就停下问用户；看板上没有、又会跨会话的事 `new` 一条再 claim，一问一答当场做完的不建；撞上占用会被拦、照提示问用户、别绕过；进度和交接写 HANDOFF，不写进条目、不写进记忆；做完 `done`，squash / cherry-pick 合并或放弃改动的收尾跑 `release`。附可直接执行的本工具绝对路径调法。
- 公司仓（遗留任务）的用法：用户定了不加锁、不新建任务，只保留已有任务直到做完；接着对应任务干、有进展更新该任务文件、做完 `done`；进度不写进记忆。

### 2.4 和别处的分工
- 进度和交接只写项目的 `HANDOFF.md`；本板只管会话互斥和待办条目，条目里不写进度。平台原生记忆和 hub 金库只存长期结论和教训。session-sweep 只是发现入口，捡起来的事落回 HANDOFF 或本板。
- 公司仓不加锁、不新建条目（用户："公司东西我记得住"）；已有的遗留任务照旧注入、更新到做完。

### 2.5 I/O / 数据契约
- 任务目录：`%LOCALAPPDATA%\ai-project-state\<仓库目录名>-<git common dir 实际路径规范化后的 sha1 前 8 位>\`（环境变量 `PSTATE_HOME` 可改根目录）。内含 `repo.txt`（记录 git common dir）、`tasks\<短名>.md`（活跃条目）、`done\`（已完成）、`locks.json`（锁状态）。在途写入的标记放在根目录的 `inflight\`。
- 条目文件：UTF-8 明文 `.md`。第一行 `# <标题>`；标题下 `- worktree: <路径>`、`- 分支: <分支>`、`- 状态: <进行中|阻塞|待办>`、`- 交接: <HANDOFF 路径>`；`## 目标` 一节。旧格式（带 `## 停在哪 / 下一步` 等节）照旧能解析和显示。人和 AI 用普通文件编辑直接改，更新时间取文件修改时间。
- 锁状态：UTF-8 JSON，仓库一份；记录活会话（会话号、进程号、进程创建时间、对话日志路径、认领的任务）、按相对路径的文件占用（占用者、所在 worktree、在途写入）、仓库开关、待通知的"被接手"。只由本工具在仓库级短锁内读改写、原子替换。
- 注入输出：`{"hookSpecificOutput": {"hookEventName": <事件名>, "additionalContext": <文本>}}`；拦截输出：`{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": <文本>}}`；放行时不输出。均为 UTF-8。

## 3. 边界 / 明确不做
- 只管个人项目；公司仓不加锁、不新建条目。
- 不记进度：进度和交接归 HANDOFF。
- 经 shell / python / 其他非原生编辑工具落盘的写入看不到：既不占用也不拦，是已知盲区。不做 Stop 时的事后补查（事后才发现、归属不清、用户中断时不触发）。
- 判断不了两个不同短名的条目是不是同一件事；任务级防重靠 AI 开工前 `claim` 同一条，是软约束。硬拦截只在文件层。
- 不按超时自动释放、不自动接手：对话日志时间只说明它多久没动。
- 不在每轮提问时做变化检测，不做带版本号的统一更新入口。
- 不进 git、不进 hub 长期记忆；不做跨机器同步。
- v0.2 锁只覆盖 Claude Code；Codex 侧只有会话开始注入。

## 4. 硬约束 + 重构自由声明
- 状态放仓库外本机目录，按 git common dir 识别同一仓库；所有 worktree 必须落到同一份。
- 锁的身份挂在会话进程上（进程号 + 进程创建时间），不靠手写认领；"检查冲突 + 登记占用"必须原子。
- 撞上占用必须拦下（不是只提醒），并给出能让用户做决定的信息。
- 钩子任何出错（参数错、超时、锁文件忙、认不出会话）都放行：退出 0、不输出，绝不因为它挡住会话。
- 只用 Python 标准库。
- **以上未列出的一切均为实现细节，重构可随意更改。**

## 5. 功能痛点 / 易错点
- 仓库识别必须用 common dir，不能用 worktree 根或分支名，否则同一仓库的几个 worktree 各看各的，等于没做。
- 不能靠"文件已经变脏"判冲突：对方写入已登记、还没落盘时文件是干净的，必须看在途占用。
- `take` 要转移所有权，不能只是"我忽略对方"：否则对方照样能接着写。
- 查不准对方死活（权限不够等）要当作活着，不能当死亡清掉。父进程链要用创建时间校验，防 PID 复用把无关进程认成祖先。
- 会话常常从公司仓目录启动、用绝对路径改个人项目：锁按被写文件的路径定位仓库，不按会话目录；会话开始注入按会话目录，所以这类会话看不到个人项目的看板，靠拦截提示和 `status --cwd` 补。
- 进度一旦写进记忆就会过期还被自动注入，误导后来的会话；条目做完必须移出活跃视图。
- 本机有 Esafenet 透明加密：`.py` 落盘是密文但 python 能跑；`.md`、`.json` 实测是明文，任何工具都能直接读写。

## 6. 平台约定
会话开始注入：
- 时机：主会话启动、恢复、清空、压缩之后。
- 需要的信息：会话当前目录、会话号。
- 预期结果：有看板条目或别的活会话时，看板和当前工作区条目全文作为上下文给到模型；没有时无感。只提示，不拦。
- 出错时：放行，不输出。
- 平台缺这项能力时：只能靠 skill 描述触发，手动跑 status。

写入前裁决：
- 时机：原生写文件工具执行之前；之后在它成功或失败时各收一次结果；会话结束时收一次。
- 需要的信息：会话号、对话日志路径、工具调用号、目标文件路径、会话目录；还要能找到本会话所在的宿主进程（父进程链上最近的宿主进程）。
- 预期结果：冲突时拦下并把理由交给模型；不冲突时静默放行并登记。
- 出错时：放行，不输出。
- 平台缺这项能力时：锁不生效；看板和 `claim` 只能作软约束。

| 平台 | 能力范围 | 支持状态 / 降级表现 | 已验证范围 |
|---|---|---|---|
| Claude Code | 会话开始注入 + 写入前裁决 + skill | 已支持 | 2026-10-09：单元 + 真 git 端到端（假进程后端）22 条；真实 headless 会话经钩子被拦下并照提示停下问用户、`take` 后重试成功、会话结束后占用释放；真实进程链认出会话进程。尚未经插件安装后的交互会话验证 |
| Codex | 会话开始注入 + skill | 注入已接线（插件钩子需先在 Codex 里信任）；锁未适配，`claim`/`take`/`release` 在 Codex 会话里不可用 | 未在真实 Codex 会话验证 |
