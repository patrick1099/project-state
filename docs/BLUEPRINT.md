# project-state 蓝图
> 活蓝图：正文永远是当前真相，改了就覆盖。只讲功能不讲实现。
> 重构照本文行为契约重写即可；未列为硬约束的一切都是实现细节，可自由更改。

## 1. 一句话
帮助用户接住当前实质想法、从本地历史找回可继续的个人事项，再决定继续聊、推进、暂放或放弃；全局事项与工程正交，无仓库也能使用。同时保留个人工程的会话互斥锁与施工待办。施工进度和交接写项目 HANDOFF，通过引用关联。事项与后台属于同一产品、同一仓库和发布，旧 session-sweep 独立产品退役。

## 2. 功能与行为 + I/O 契约

### 2.1 会话互斥锁（自动）
- 作用范围：只在个人项目生效。个人项目 = 目标文件所在 worktree 的根有 `docs/BLUEPRINT.md`，或目标文件同目录有 `*.BLUEPRINT.md`；仓库级开关 `lock on|off|auto` 可强制开 / 关 / 回到按蓝图判断，off 优先。不在 git 里、或不是个人项目的写入，一律放行、什么都不输出、不留任何状态。
- 写入前裁决：会话每次用 Write / Edit / MultiEdit / NotebookEdit 写文件之前，把这个文件按"在 worktree 里的相对路径"登记到本会话名下——不同 worktree 里的同一相对路径算同一个文件（个人仓每件活开一个 worktree，冲突要到合并时才炸）。这个文件已被另一个活会话占着 → 拦下这次写入，拦截理由给出：文件、占用者会话号、它在哪个 worktree、认领的任务、对话日志最后更新时间、是否还有写入在执行中或等待批准；并要求 AI 停下把情况告诉用户、问等对方还是接手，用户说接手就跑 `take <会话号>` 再重试，不许换 shell / python 等别的工具绕过。
- 登记即生效：登记发生在写入之前、和裁决一起原子完成；对方写入还在执行中或等待批准时，即使文件看起来没变也照样互斥。写入失败时，只撤销这次新建、且从没写成过的占用；之前写成过的占用不因一次失败而撤销。
- 占用什么时候释放：
  - 占用者会话的进程没了（窗口关掉、崩溃）——查不准死活时当作还活着，不释放；
  - 占用者会话结束（含 `/clear` 换会话）；
  - 占用者那个 worktree 已不存在；或那个文件在它的 worktree 里干净、不是被忽略的文件、其分支已并进集成分支（本地 `main`，没有就 `master`），且没有在途写入；
  - `release`（用 squash / cherry-pick 合并、或放弃改动时收尾用）、`take`（被别人接手）。
  - 不按超时释放。会话闲置再久，只要窗口开着就还占着，看板显示对话日志最后更新时间，由用户决定是否接手。
- 同一家不互斥：占用者是本会话进程本身（同进程的子代理）或本会话的祖先进程（本会话起的 headless 子会话去写父会话占着的文件）→ 放行，占用仍归原占用者。同一个父会话起的两个 headless 子会话之间照常互斥。
- 接手（take <会话号前缀|条目短名>）：用户同意后，把对方在本仓库的全部文件占用和任务认领转到本会话名下；对方之后再写这些文件会被拦。对方下一次在本仓库写任何文件时，会被拦一次并被告知"用户已让会话 X 接手你在这个仓库的活"，重试即可继续别的事。对方还有在途写入时提示"已经放行的写入撤不回"。找不到唯一的活会话 / 认领时退出 1（会话可能已结束，直接重试即可）。

### 2.2 看板
- 看现场（status）：在仓库内任意目录运行 → 打印仓库名与任务目录；列出 git 登记的每个 worktree（路径、分支、HEAD 短哈希、"干净"或"改动 N，未跟踪 M"，目录不存在或读不了就明说），当前所在的那个带 `*`；有活会话时列出每个活会话：会话号（本会话标"（本会话）"）、认领的任务、占用几个文件、对话日志最后更新时间；再列看板条目：短名、标题、状态、被哪个会话认领、所属工作区（当前的标"（当前）"）、多久前更新，条目里有「停在哪 / 下一步」节时显示其第一行。条目 7 天以上没改过标"久未更新，内容可能过期"；条目登记的工作区已不在 git 登记里标"工作区已不在 git 登记里，基线待核实"。已经死掉的会话在读看板时顺手清掉。
- 新建条目（new <短名> --title <标题> [--status 待办|进行中|阻塞] [--force]）：默认状态 `待办`。按模板生成条目文件，自动填上当前 worktree 根、当前分支和 `<worktree>/docs/HANDOFF.md`（进度正文写那里），打印文件路径。不是个人项目时拒绝并退出 1（用户定了公司仓不新建条目），加 `--force` 才建。短名只许字母、数字、下划线、点、横线，不合法退出 2；同名已存在退出 1，不覆盖。
- 认领（claim <短名>）：本会话认领一条，条目状态改为 `进行中`。看板上没有这条退出 1（先 new）；已被另一个活会话认领退出 1，并告诉 AI 停下问用户、接手用 `take`。
- 放掉（release）：放掉本会话在本仓库的任务认领和所有没有在途写入的文件占用。
- 做完（done <短名>）：条目移到 `done/<YYYYMMDD>-<短名>.md`，此后不再出现在看板和注入里，认领随之解除；不存在退出 1。
- 任务目录（path）：打印本仓库的任务目录（不存在就建）。
- `claim` / `take` / `release` 只能在 Claude Code 会话里运行（靠会话号环境变量认出自己），认不出退出 1。所有命令默认按当前目录识别仓库，`--cwd <目录>` 可指定；从哪个 worktree、哪个子目录进来，看到的都是同一份。

### 2.3 会话开始注入
- 从标准输入读宿主 JSON；全局有 open/decided 时输出计数及入口，不扫描历史，无 Git 也可提示。旧仓库看板仅在有条目或其他活会话时输出：看板 ＋ 当前 worktree 名下条目的全文（合计超过 4000 字就只列路径并要求读完，绝不截断）＋ 用法。
- 个人项目的用法：开工前对一下活会话和条目；要做的事在看板上先 `claim`，被拒就停下问用户；看板上没有、又会跨会话的事 `new` 一条再 claim，一问一答当场做完的不建；撞上占用会被拦、照提示问用户、别绕过；进度和交接写 HANDOFF，不写进条目、不写进记忆；做完 `done`，squash / cherry-pick 合并或放弃改动的收尾跑 `release`。附可直接执行的本工具绝对路径调法。
- 公司仓（遗留任务）的用法：用户定了不加锁、不新建任务，只保留已有任务直到做完；接着对应任务干、有进展更新该任务文件、做完 `done`；进度不写进记忆。

### 2.4 和别处的分工
- 进度和交接只写项目 HANDOFF；全局事项引用它并保留有时间的历史停点，旧施工条目不复制进度。平台原生记忆和 hub 金库只存长期结论和教训。后台来源判断仅作提示，不替代当前 AI 审阅与事项决定。
- 公司事项不自动收录；旧公司仓不新建施工条目、不自动加锁，已有遗留任务照旧注入并做完归档。

### 2.5 I/O / 数据契约
- 任务目录：`%LOCALAPPDATA%\ai-project-state\<仓库目录名>-<git common dir 实际路径规范化后的 sha1 前 8 位>\`（环境变量 `PSTATE_HOME` 可改根目录）。内含 `repo.txt`（记录 git common dir）、`tasks\<短名>.md`（活跃条目）、`done\`（已完成）、`locks.json`（锁状态）。在途写入的标记放在根目录的 `inflight\`。
- 条目文件：UTF-8 明文 `.md`。第一行 `# <标题>`；标题下 `- worktree: <路径>`、`- 分支: <分支>`、`- 状态: <进行中|阻塞|待办>`、`- 交接: <HANDOFF 路径>`；`## 目标` 一节。旧格式（带 `## 停在哪 / 下一步` 等节）照旧能解析和显示。人和 AI 用普通文件编辑直接改，更新时间取文件修改时间。
- 锁状态：UTF-8 JSON，仓库一份；记录活会话（会话号、进程号、进程创建时间、对话日志路径、认领的任务）、按相对路径的文件占用（占用者、所在 worktree、在途写入）、仓库开关、待通知的"被接手"。只由本工具在仓库级短锁内读改写、原子替换。
- 注入输出：`{"hookSpecificOutput": {"hookEventName": <事件名>, "additionalContext": <文本>}}`；拦截输出：`{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": <文本>}}`；放行时不输出。均为 UTF-8。

### 2.6 全局待续事项与历史回顾
- 当前会话主动收录：个人想法已有实质内容且值得跨会话继续 → 当前 AI 形成 open 卡片，记录动机、有效结论、未定问题、带时间的历史停点和来源。收录不等于承诺；公司事项不自动收录。事项关联 0..N 个工程路径，可无 Git；会话、仓库、worktree 都不是事项身份。
- 历史发现：给 Claude/Codex 本地历史范围 → 返回有界纯正文、原生消息来源、内容版本、覆盖统计和续页游标。当前 AI 阅读、筛选、拆分与归并后 add；用户看可继续的卡片，不逐页筛原文。交互 discover 不做语义判断、不另调模型；后台判断单独显式启用，不自动全量导入事项。
- 来源与时效：保留原话的来源平台、会话、锚点、时间、角色、摘录及哈希；来源核验失败明确标未核验。核验只证明原话出处，不证明其授权含义。AI 建议单独标识；历史卡可保留带时间和来源的当时停点，声称当前现状或真正恢复执行前才由当前 AI 查 Git、成果和 HANDOFF。历史 stopped_at 必须带截至时间，不能冒充当前进度。
- 归并与幂等：重复收录相同标题及来源可返回已有 ID；同锚点拆成不同事项须明确 --distinct，追加到已有事项用 --into ID --rev N，且仅追加来源。改摘要走 set。新来源不能重开 parked/dropped/done；同名仅提供相似提示，不自动合并。
- 四个选择：continue 只返回卡片，状态和版本不变；do → decided，仅记录决定，不创建任务或执行工作；later → parked，默认隐藏但 list --all/--state parked 可找回；drop → dropped，保留决定记录。do/later/drop 需要用户原话及来源。
- 完成与重开：done 必须带非空 evidence，可由 assistant 基于实际证据记完成，不捏造用户确认；若附用户原话，照样核验。reopen 将 parked/dropped/done 设为 open，需要明确用户原话。dropped/done 要再选 do/later/drop，先显式 reopen。
- 默认可见性：list 默认显示 open/decided 并返回各态计数；show/continue 返回卡片、来源、决定记录及引用 HANDOFF 的存在性和修改时间，不读取其内容、不执行任务。写入后读取回执并 show 确认，才可说已记下。
- 历史已审：discover 只读，不自动 seen；当前 AI 完整审阅会话内容版本后显式 seen。相同版本下次跳过，内容变化须重审；分页中更新 seen 可以继续游标，历史内容变化使旧游标失效。当前环境会话默认排除。
- 历史边界：普通 discover 每次读取所选 roots 内全部 JSONL，没有扫描缓存；limit/max_chars 仅限制返回页，files 可精确抽样。过滤可识别的 agent/headless、工具、系统、推理及压缩副本；旧格式人类身份不确定保留 legacy/unknown，不声称完整覆盖；本地缺失或删除不可恢复。导入的旧摘要与 checked/closed 仍只作来源资料及提醒关闭，不代表事项 done 或会话 seen。

新增 I/O 契约：
- 命令入口为 `thread add/list/show/set/choose/done/reopen/discover/seen`；后台及冻结录入为 `sweep` 子命令；复杂输入为 UTF-8 JSON 的 --input-file 或 stdin。JSON 输出信封为 ok/data/error/meta；成功 stdout，失败 stderr；退出码 0/1/2 = 成功/运行失败或冲突/输入错误。--ai-help/--help 始终输出帮助文档。
- add 必需 title/sources；可编辑字段为 title/motivation/confirmed/questions/stopped_at/next_suggestion/paths/handoff。confirmed 是 {said, source} 数组，回读含 verified/verification_note；questions/paths/handoff 为字符串数组，next_suggestion 输入为文本、保存带 AI 标记。
- source 必需 platform/session/anchor/time/role/excerpt/excerpt_hash，path 可选但原话核验需要它；excerpt_hash = UTF-8 摘录 SHA-256。选择输入为 said/source，said 须逐字包含于用户摘录；done 为 evidence 字符串数组并可附 said/source。
- discover 可用 roots/files/since/limit/max_chars/cursor/exclude_sessions/sweep_state；返回 sessions/next_cursor/coverage/warnings，消息含 source 与分片范围。seen 必需 platform/session/version。详细调用示例见 skill。
- 全局库为 `PSTATE_HOME/threads/threads.json`（默认根同旧任务目录），备份为 bak.json，schema=1；事项有稳定 id、rev、state、sources 与 log。旧 tasks/locks 数据与入口继续兼容，无自动迁移。
- 修改使用版本检查，失败不覆盖损坏或未知结构；主库缺失而备份存在时要求显式恢复。变更命令的 dry-run 与实际执行共用校验及事务路径，不写业务状态，仅可能创建协调锁。替换后读回核验；replaced_unverified 必须先核实际落库，不盲重试。

### 2.7 后台发现与联合回顾页

- 给出已启用的状态根与输出目录 → 联合页面显示完整事项卡片和待审来源摘要。事项关联 0..N 工程，一会话可有多事项；部分关联显示“已关联N项，余部未审”。只有完整审过相同正文版本，才因关联自动收起已经展示的来源。
- 旧后台 AI 判完成/放弃的来源沿用默认隐藏，公司来源也不列页；完整摘要、错误、关闭和原页资料始终可从 sources 查询，原文仍在时可 discover。筛选不写事项状态或 seen；新来源不复活 parked/dropped/done。
- 勾选关闭该活动版本整条提醒（含未识别余部），取消恢复；不改变事项、不代表已审。写页前最后读主清单、已处理页及全部周档勾选；同条冲突以恢复为准。最近窗口按天显示，更早按来源原时间周归档；只删除带工具标记的空归档。
- 来源身份为平台+原生会话ID。review_version 是正文内容版本（兼容原 version hash），activity_version 包括工具活动；后台按后者判断新活动，seen 只认前者。旧 summary.version 时间戳与 sid@timestamp 勾选保留，首次映射固定，不能因同时间戳新活动继承旧关闭。
- 来源摘要永久保留，原文消失标不可用而不删摘要，原文恢复可撤标。迁移使用来源原时间；未变来源沿用判断，不重复调用模型。
- 后台保留配置中的 recap/自答策略、owner 线索、成功写路径、入口信息、预算、超时、失败上限及文档疑似未同步提示。新鲜 recap 必须晚于最后有效活动；无新鲜 recap 才在支持的平台分叉自答。模型隔离调用，不触发用户钩子/插件/工具，不改原会话；Codex 当前只支持交互发现。
- 配置缺失、类型错、必需命令/模型空白或数值非有限时，在业务写入前拒绝；来源资料损坏时明确失败，保留原字节。合法旧摘要的可选缺省和未知字段继续保留。

### 2.8 冻结录入、迁移与唯一写者

- `sweep review` 接受 platform/session/review_version/files/items/complete 六项冻结 JSON。每个 item 含原 add payload，可附 into/rev 或显式 distinct；先核原文、摘录与版本，逐项保存并独立回读，全部成功且 complete=true 最后写 seen。完整审阅无事项时允许空 items；部分成功保留已存项但不 seen，先核回执再原输入重放，不能重命名重拆。
- 全局事项库仍为 schema1，旧 tasks/locks 不迁移。永久资料在 `PSTATE_HOME/sweep/sources.json`（version1），保存摘要、判断、错误、关闭、原时间、未知字段与导入旧页；辅助资料不形成第二事项生命周期。
- `sweep import-legacy/reconcile` 只读显式旧 state/out，预演和实际共用写路径；保留原主清单、已处理页、完整周档、孤立旧档及原路径资料。合并冲突保留当前数据，不自动删除原资料。
- 安装/发布不导入、不启用。`switch` 显式声明 state/out/token 归属；先永久资料与 switching 状态，再归属标记、页面，最后 enabled。中断后的普通 run 拒绝写，显式 switch 可前向恢复。未知旧 run.lock 拒绝接管，不按年龄判断旧进程结束。
- 整轮后台按规范化物理输出路径互斥，包括不同状态根与 junction 别名；模型调用不占事项库短锁。底层写页/删归档函数同时检查 lease、activation、owner 与实际路径，dry-run 也检查；跨目录逃逸或无法读回的页明确拒绝。
- `rollback` 最后吸收当前勾选并暂停新 writer，保留当前页、来源资料和新事项决定；不恢复旧快照或旧 writer。恢复用显式 switch 前向继续。
- `run --no-judge` 不调模型；dry-run 不写业务资料/页、不调付费模型，仅可能建协调锁。JSON 信封及 0/1/2 退出码与事项命令一致。旧 session-sweep 顶层、隐藏启动器、模块与底层写/安装入口均拒绝执行。
- 新计划任务只可从稳定活源的明文 run_hidden.pyw 注册，拒绝 worktree/版本缓存（含预演）。隐藏入口无窗口拉起固定白名单 Python、返回真实退出码，诊断写 `sweep/last_launch.log`；注册任务不等于启用 writer。

## 3. 边界 / 明确不做
- 全局事项面向个人讨论与决定，允许无工程；公司事项不自动收录。旧工程任务/锁规则继续独立生效。
- 不复制施工进度：进度和交接归 HANDOFF；事项的历史停点必须注明截至时间。
- 经 shell / python / 其他非原生编辑工具落盘的写入看不到：既不占用也不拦，是已知盲区。不做 Stop 时的事后补查（事后才发现、归属不清、用户中断时不触发）。
- 判断不了两个不同短名的条目是不是同一件事；任务级防重靠 AI 开工前 `claim` 同一条，是软约束。硬拦截只在文件层。
- 不按超时自动释放、不自动接手：对话日志时间只说明它多久没动。
- 后台只在显式切换后按配置运行，不暗调额外模型、不做 GUI、不增加 API/BYOK、不自动执行事项或全量导入事项；旧施工看板不增加每轮变化检测。
- 不进 git、不进 hub 长期记忆；不做跨机器同步。
- 锁仍只覆盖 Claude Code；Codex 可用全局 thread CLI/skill 与开始注入壳，未实现施工锁。

## 4. 硬约束 + 重构自由声明
- 状态放仓库外本机目录；全局事项与工程正交，不依赖 Git。旧工程任务/锁按 git common dir 识别同仓，所有 worktree 落到同一份。
- 锁的身份挂在会话进程上（进程号 + 进程创建时间），不靠手写认领；"检查冲突 + 登记占用"必须原子。
- 撞上占用必须拦下（不是只提醒），并给出能让用户做决定的信息。
- 钩子任何出错（参数错、超时、锁文件忙、认不出会话）都放行：退出 0、不输出，绝不因为它挡住会话。
- 只用 Python 标准库。
- 以上未列出的一切均为实现细节，重构可随意更改。

## 5. 功能痛点 / 易错点
- 仓库识别必须用 common dir，不能用 worktree 根或分支名，否则同一仓库的几个 worktree 各看各的，等于没做。
- 不能靠"文件已经变脏"判冲突：对方写入已登记、还没落盘时文件是干净的，必须看在途占用。
- `take` 要转移所有权，不能只是"我忽略对方"：否则对方照样能接着写。
- 查不准对方死活（权限不够等）要当作活着，不能当死亡清掉。父进程链要用创建时间校验，防 PID 复用把无关进程认成祖先。
- 会话常常从公司仓目录启动、用绝对路径改个人项目：锁按被写文件的路径定位仓库，不按会话目录；会话开始注入按会话目录，所以这类会话看不到个人项目的看板，靠拦截提示和 `status --cwd` 补。
- 进度一旦写进记忆就会过期还被自动注入，误导后来的会话；条目做完必须移出活跃视图。
- 本机有 Esafenet 透明加密：`.py` 落盘是密文但 python 能跑；`.md`、`.json` 实测是明文，任何工具都能直接读写。

## 6. 平台约定
会话开始注入：
- 时机：主会话启动、恢复、清空、压缩之后。
- 需要的信息：会话当前目录、会话号。
- 预期结果：全局 open/decided 有内容时提示计数及入口，不扫描历史；旧仓库有看板条目或别的活会话时，再注入看板及当前工作区条目。只提示，不拦。
- 出错时：放行，不输出。
- 平台缺这项能力时：只能靠 skill 描述触发，手动跑 status。

写入前裁决：
- 时机：原生写文件工具执行之前；之后在它成功或失败时各收一次结果；会话结束时收一次。
- 需要的信息：会话号、对话日志路径、工具调用号、目标文件路径、会话目录；还要能找到本会话所在的宿主进程（父进程链上最近的宿主进程）。
- 预期结果：冲突时拦下并把理由交给模型；不冲突时静默放行并登记。
- 出错时：放行，不输出。
- 平台缺这项能力时：锁不生效；看板和 `claim` 只能作软约束。
